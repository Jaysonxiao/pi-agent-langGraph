## 顺序与完成标准

建议顺序：**服务管理 → 基线验证 → 共用审批能力 → 文件修改 → 命令审批 → 最终复验**。

任务 2 分为两轮：前一轮发现环境和真实模型的既有问题，后一轮验证新增功能。任务 4、5 共用持久化审批与会话恢复能力，先建立这一层，避免两套接口和状态规则。文件修改先于命令执行，便于先用可控的单文件副作用检验审批闭环，再处理进程树、超时和取消。

|---|---|---|---|---|
| A | 1 | 服务 `status / stop / restart` 与启动冲突诊断 | 能识别、停止和重启本项目服务；暂停进程、占用数据库、占用端口有可操作提示；不误停其他进程 | completed |
| B | 2（基线） | Linux/Windows 实际 CI、真实 compatible Web 基线 | 保存实际运行证据；验证流式、取消、刷新与显式恢复；未执行项明确保留 | 本机/live 已完成；平台 CI pending（W1） |
| C | 4、5 的共用前置 | 持久化提案、审批 API、异步等待与恢复 | 提案重启可见；批准/拒绝去重；普通恢复不能绕过审批；执行不因重连或重启自动重放 | completed |

| E | 5 | Web 命令提案、批准执行、取消与结果 | exact argv/cwd 可审查；一次认领；输出有界；停止/超时回收进程树；不确定结果不自动重跑 | completed |

## 计划制定时的基础与缺口（历史）

- [启动脚本](../../scripts/start-web.sh)已支持 macOS/Linux；[Web 入口](../../src/pi_agent/web/app.py)以数据库文件锁限制同库 Web 实例，但还没有服务管理入口。用户实际遇到的锁占用由暂停的旧服务造成，删除锁文件不能解决进程仍持有锁的问题。
- [上一轮交付](web-continuation.md)已有流式文本、显式恢复和完成 checkpoint 分支，以及三平台 Web CI 配置；本机验证与远端 CI、真实模型验证必须分别记录。
- [文件审批图](../../src/pi_agent/graph/file_approval.py)是同步、内存检查点的独立教学图，不能直接视为 Web 持久审批。[文件规划](../../src/pi_agent/tools/file_mutation.py)与[批准后写入](../../src/pi_agent/tools/file_apply.py)可复用，但需要补持久提案、异步编排和执行结果恢复。
- [命令审批存储](../../src/pi_agent/tools/command_approval.py)已有 propose/claim/finish 和 CLI 人审；当前提案 ID 按会话、工作区、参数生成，同会话重复相同命令会得到同一提案。Web 需要区分一次操作重试与后续独立操作，并补充取消接线、失败状态和有界输出记录。
- [异步进程执行](../../src/pi_agent/tools/async_process.py)已有超时与进程树清理；命令审批包装层需要接入当前 Web 运行的取消令牌。现有命令 cwd 就是绑定工作区，本轮先沿用该范围。

## A：先解决服务管理与锁占用

**目标与范围**：保留现有无子命令启动方式，增加统一 Python 管理入口，由 Bash/PowerShell 脚本转交 `status / stop / restart`。查询与停止不应安装 Node 依赖或构建前端。

交付内容：

1. 为每个数据库保存服务实例信息：PID、进程启动身份、数据库规范路径、监听地址、实例标识和必要的非敏感启动配置。记录位置在工作区之外，沿用数据库管理范围。
2. `status` 区分未运行、健康、暂停、无响应、过期实例记录与资源被其他进程占用；显示对应数据库、地址和可确认的进程信息。旧版服务没有实例记录时提供诊断提示，不能仅凭端口或 PID 自动认领。
3. `stop` 验证进程身份后优雅退出并等待释放资源；对确认属于本实例的暂停进程，先恢复再退出。超时后报告实际状态，强制停止作为显式选项。
4. `restart` 先确认旧实例退出、资源释放，再按明确配置启动；失败时输出所在步骤和解决路径。保持现有前台启动方式，本轮不引入系统后台守护服务。
5. 启动冲突转换为简洁错误，说明数据库/端口与已知实例；不静默换库、换端口，不靠删除文件锁绕过互斥。

**验收**：真实隔离服务的 start/status/stop/restart；POSIX 暂停进程；过期 PID、PID 身份不匹配、其他程序占端口；重复停止；活动运行取消与停机清理；数据库内容保留。平台特有用例在对应平台执行。

**主要位置**：`src/pi_agent/web/`、`scripts/start-web.sh`、`scripts/start-web.ps1`、`scripts/web_startup_smoke.py`、`tests/web/`、运行文档。

## B：建立实际验证基线

**目标与范围**：验证上一轮功能及 A，先找出现存平台/Provider 问题，避免将它们混入审批功能开发。

- 在 Linux/Windows 实际运行已有 CI 与服务管理 smoke，保留运行链接、系统/Python/Node 版本及结果。CI 文件存在不代表 CI 已执行。公网部署不在本轮范围，M11 D1–D3 只按实际对应证据逐项更新。
- 在显式配置 `.env`、`PI_AGENT_LIVE=1` 且获得真实调用授权后，用合成工作区和独立数据库验证 compatible Web：只读工具闭环、流式展示、取消、刷新、重启后显式恢复及分支隔离。
- live 与离线测试分别记录；日志不保存密钥或私有正文。远端故障、限流等只按实际覆盖记录，不以一次成功请求推断全部容错成立。

**验收**：可复现的独立记录，实际失败先修复并复验；缺少 runner/配置/授权时记录未执行原因。既有历史测试数保持原样。

## C：建立共用持久化审批闭环

**目标与范围**：把“生成提案 → 等待用户 → 执行认领 → 保存结果 → 回灌模型”接入异步 Web 请求链。默认仍仅开放只读工具，修改/命令能力由服务端显式启用。

交付内容：

1. 定义共用提案 DTO、存储接口和浏览器安全投影；绑定会话、运行、tool-call/操作 ID、工作区、提案类型、内容版本与当前能力策略。相同操作重试去重；不同操作允许产生相同内容的新提案。
2. 增量迁移数据库并保留旧命令提案与 CLI 行为。状态区分等待决策、拒绝、已认领、成功、失败、取消及结果不确定；具体枚举按现有存储复用，不建立相互矛盾的两套真相。
3. 增加提案列表/详情、批准/拒绝、结果接口，沿用 Web 认证与请求约束。服务端验证提案归属、展示版本与状态；重复点击返回同一结果，过期决策拒绝。
4. 在异步图中设置可持久恢复的审批等待边界；等待时不长期占用模型连接。界面区分“等待审批”和“运行中断”；普通 resume 不得跳过决策，分支不继承待执行授权。
5. 浏览器审批卡展示完整可审查信息、结果与错误，通过快照/SSE 恢复；刷新、重连、多窗口和重复点击不重复执行。
6. 一次模型回复中有多个工具调用时明确执行次序，首版修改/命令操作串行审批；拒绝结果正常回灌模型，已完成结果恢复时不重做副作用。
7. SQLite 认领与文件/进程副作用不属于同一事务；崩溃留下不确定状态时要求人工核对，不承诺跨资源 exactly-once，也不自动重放。

**验收**：先用确定性测试驱动真实异步图、SQLite 和 Web API；覆盖重启前后 pending、决策去重/冲突、跨会话决策、归档/工作区变更、普通恢复绕过尝试、多个工具调用与结果回灌。测试真实状态变化，不只模拟界面响应。

## D：交付 Web 文件修改与审批

**首版范围**：工作区内单个 UTF-8 文本文件的创建/完整替换和唯一精确 edit。模型只能准备提案；用户在 Web 查看 diff 并决定。本轮不含删除、二进制文件、多文件批量提交或自动批准。

交付内容：

1. 复用 FileChangePlanner，提案保存 before/after hash、内容与操作身份；界面显示相对路径、创建/修改类型、diff、版本及大小。设置明确的文件/提案大小上限，超限拒绝；截断展示不能隐藏无法审查的修改。
2. 对读取、提案和最终写入统一工作区与敏感路径策略；禁止修改 `.env`、密钥、`.git` 等受保护内容，执行前再次校验路径与 symlink。沿用现有编码/换行处理并检查替换后文件权限的合理保留。
3. 批准时重新读取并校验 before hash，再原子写入；同一目标的本服务并发写入串行化。外部修改冲突需重新生成提案，旧批准不能沿用。
4. 记录写入结果并回灌工具消息；拒绝、冲突和失败有明确终态。写入完成但结果尚未落库时的崩溃按 C 的不确定状态处理，不能盲目重写。

**验收**：真实临时文件验证批准/拒绝、新文件、唯一替换、版本冲突、受保护路径、symlink、并发提案、换行与权限、写入失败；故障注入覆盖认领后/替换前/替换后重启。浏览器 E2E 验证 diff、审批、刷新与结果回灌。

## E：交付 Web 命令审批与执行结果

**首版范围**：持久化结构化 executable/argv 提案，cwd 固定为绑定工作区；人工批准后调用现有受控 subprocess。允许列表由服务端配置，默认关闭命令能力；批准的进程仍拥有本机用户权限，工作区路径约束不等于 OS 沙箱。

交付内容：

1. 界面显示精确 argv 各参数、cwd、超时与输出上限，不只显示容易产生歧义的拼接命令字符串。提案不得包含密钥，审批接口不接受替换参数；执行前再次校验展示版本、工作区和当前 allowlist。
2. 扩展/适配现有 CommandApprovalStore 的操作身份和持久结果，保留旧 CLI 数据与交互审批语义。合法的新操作可重复相同命令，重试同一次操作只执行一次。
3. 共享当前 Web 运行的取消令牌；停止、服务退出与超时都进入进程树回收流程。分别记录成功、非零退出、失败、超时、取消及清理失败。
4. 保存有界 stdout/stderr、退出码、截断信息与耗时，界面展示并回灌模型；不在 lifecycle telemetry 中复制正文。
5. 重启后 pending 可继续审批；已认领但结果不明只显示核对状态。批准、恢复、浏览器重连均不能自动重复启动该进程。

**验收**：用确定性的辅助进程验证精确参数、cwd、allowlist 拒绝、重复批准、不同操作重复相同参数、输出截断、非零退出、超时、取消、子进程清理及重启不重放；在实际 Windows/Linux 上执行进程树用例。浏览器 E2E 覆盖批准/拒绝、停止和持久结果。

## F：最终复验与交付证据

每阶段先跑相关聚焦测试与必要静态检查；涉及前端时执行单测、构建，涉及交互时执行 E2E。最终组合验证的计划命令为：

```bash
uv run --extra web pytest -q --basetemp=.pytest-tmp -W error::ResourceWarning
uv run mypy src tests scripts
uv run ruff check .
uv run ruff format --check .
uv run python scripts/web_startup_smoke.py
cd web-ui
npm run test
npm run build
npm run test:e2e
```

还需复验 CLI/TCP 只读链路、原 CLI 命令审批、旧数据库迁移与 Web 停机恢复，确认共用组件改动没有改变既有入口契约。真实 compatible 在合成工作区内验证文件/命令提案产生、人工决策、结果回灌及取消；具体命令受测试专用 allowlist 限制。

新增独立验收记录，按实现日期、实际执行日期与用户验收分别记录：本机离线、平台 CI、真实模型三类证据；说明未执行项、失败原因及剩余范围。只关闭实际验证对应的遗留项，不改写过去的验收数字。

## 本轮边界与执行批次

不包含会话全文搜索/导出、全面模型质量评测、公网部署、多用户、任意 shell、后台系统服务或自动批准。优先交付可独立审查的六个批次：A 服务管理、B 基线记录、C 审批基础、D 文件修改、E 命令审批、F 最终验收。C–E 默认功能开关关闭，验证后再按服务端配置显式启用。

计划编写时：仅完成代码基础检查和规划，A–F 均为 pending。随后用户授权执行：A/C/D/E 已完成代码与本机验证，B 的真实 Web 基线已通过；F 的本机组合复验已通过，平台 CI 未执行。此前触发 CI 的分支推送被自动审批审查拒绝；随后用户要求归档并仅合并本地 main，不 push。已交付范围归档，未执行项转入后续清单，不将原跨平台完成标准视为达成。详细命令与失败修复保留在独立验收记录。
