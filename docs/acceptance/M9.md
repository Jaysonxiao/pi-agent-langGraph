### M9.1 模块协作与失败路径

```text
应用装配 register(name, async handler)
              ↓ 保留注册顺序、拒绝重名
节点/runner 构造 HookEvent（M9.1 时尚未接入；M9.2–M9.3 后接入）
              ↓
HookRegistry.dispatch(event)
  ├─ handler 成功 → 下一个
  ├─ 普通 Exception → 追加 HookFailure(type only) → 下一个
  └─ CancelledError → 原样传播 → 停止后续 handler
```

`HookEvent` 是 frozen dataclass，只暴露 phase、thread/run/sequence、node、可选 tool identity/outcome。它没有通用 payload，避免在 telemetry/redaction 尚未完成前把 prompt、凭据、工具参数或输出引入扩展面。`HookFailure` 只保留 hook name、phase 和异常类型，不保留可能含密钥的异常正文。

### M9.2 完成记录：Provider run lifecycle

**要实现的功能**：让每次 `stream_provider_session()` 调用在图开始前派发一次 `run_start`，并在正常结束、图返回失败状态、异常/取消或消费者提前关闭时派发且只派发一次 `run_end`。两事件共享 `thread_id` 和本次调用唯一的 `run_id`，sequence 递增。hook 普通异常由 M9.1 registry 隔离；取消必须继续传播。事件只含关联元数据，不写入 checkpoint state。

**实现接口**：`src/pi_agent/cli/runtime.py` 的 `stream_provider_session` 接受可选参数 `hooks: HookRegistry | None = None`。该函数创建每次调用的 `run_id`，用 `options.session_id` 作为 `thread_id`，并通过 `HookRegistry.dispatch(HookEvent(...))` 派发生命周期事件。关联信息不进入 `AgentState` 或 SQLite checkpoint。

**输入/输出**：输入是现有 Provider options、已注入 async model、可选 registry；输出仍是 `AsyncIterator[StreamEvent]`，额外副作用只有传给 registry 的 `run_start`/`run_end`。`run_end.outcome` 使用现有 `HookOutcome`：图状态成功为 `completed`，图状态失败或普通运行异常为 `failed`，任务取消及消费者关闭为 `cancelled`。

**约束**：开始事件必须先于图运行；结束事件在每条终止路径都恰好一次；开始/结束共享身份，sequence 严格递增；消费者关闭时先关闭底层图 iterator，再完成 run 结束派发；不要吞掉 `asyncio.CancelledError`/LangGraph 的取消包装；hook 事件不得携带 prompt、凭据、模型回复、工具参数或工具输出。无 registry 时现有行为保持不变。

**测试证据**：`tests/integration/test_provider_lifecycle.py` 覆盖完成路径及连续两次运行（ID 关联且 run_id 不同）、模型令图进入 failed 状态、取消、消费者 `aclose()`。用户于 2026-09-24 报告执行 `uv run pytest tests/integration/test_provider_lifecycle.py -q --basetemp=.pytest-tmp-m92` 得 **4 passed in 0.74s**。该结果是用户执行报告，本轮未独立重跑；mypy/Ruff 尚未作为 M9.2 验证执行。

**代码审阅**：Provider session 每次创建 UUID run_id；在首个流事件前派发 `run_start`，在 finally 中派发一次 `run_end`；先关闭底层图流，再结束 run。完成状态从图更新读取，普通失败、LangGraph 取消包装和 `GeneratorExit` 分别映射到失败/取消终态。HookEvent 仅包含关联元数据；普通 handler 异常由 registry 隔离，取消继续传播。M9.2 暂不接触 model/tool hooks、telemetry 或 eval。

**验收状态**：四种终止情况均只有一个正确关联的 `run_end`，成功/失败/取消终态准确，取消继续向调用者传播；M9.2 目标测试已由用户报告通过。完整静态检查和 M9.1 回归在本轮未运行。

### M9.6 生命周期 spans 接入与 R1 修正

**整体位置**：Provider 有序地产生一个 run 内的 `run_start → before_model → after_model → before_tool → after_tool → run_end` hook 事件；telemetry package 提供 root/child span port 与脱敏 adapter。本切片补上两侧的 adapter，使这些生命周期事件能形成同一 trace 下可查看的 model/tool spans。

**贯穿场景**：`stream_provider_session()` 执行一次 `read probe.txt → model summary`。调用方注册 telemetry hook 后，run_start 创建 root span；每次 before_model/after_model 创建并结束 model child；before_tool/after_tool 创建并结束带 tool identity 的 child；run_end 结束 root。所有记录共享 trace ID，child 的 parent 指向该 run root；记录只留 thread/run/tool identity，不留 prompt、tool args、文件内容或 reply。sink 的普通错误继续沿用 HookRegistry 的隔离契约。

**Pi 到 Python 的映射**：Pi telemetry 抽象从运行作用域创建 trace 上下文并沿调用树传播；本项目 M9.1 将受限 identity 放进 HookEvent，M9.3.4 将后端抽象成 `TelemetryPort`。新增的 `TelemetryLifecycleHook` 是显式注册的薄 adapter：它消费事件、管理 root 与未结束 child span，不侵入 graph state/checkpoint，也不让 graph 节点依赖某家 telemetry SDK。

**已交付主路径**：新增 `TelemetryLifecycleHook(telemetry)` 与 async `handle(event)`。run_start 创建 `agent.run` root；model/tool before/after 创建、配对并结束 child；run_end 结束 root，并清理未配对 child。root/children 使用同一 trace ID，child 的 parent 指向 root；tool span 只记录工具名与 call ID。telemetry failure 沿用 HookRegistry 的普通异常隔离。

**测试文件**：`tests/integration/test_telemetry_lifecycle.py` 用 scripted async model 驱动真实 Provider session 的 read 工具往返；断言 1 个 root、2 个 model child、1 个 tool child、共同 trace/parent 关系、工具 identity、全部成功 outcome，以及 synthetic prompt/文件正文不会进入 span attributes。另一个用例注入 throwing telemetry sink，确认 Provider run 仍以 completed 结束。

**主路径验收证据**：用户于 2026-09-24 报告执行 `uv run pytest tests/integration/test_telemetry_lifecycle.py -q --basetemp=.pytest-tmp-m9` 得 **2 passed in 0.55s**。本轮未独立重跑。

**代码审阅**：hook handler 按 run ID 管理 root、按 run/phase/model node 或 tool call ID 配对 child；重复/缺失事件安全忽略。InMemoryTelemetry 保存前递归脱敏 attributes。read-tool round-trip 证明一个 run 下有 2 个 model child 和 1 个 tool child，共享 root trace/parent；throwing start-span sink 用例证明 hook 异常不会令 Provider run 失败。R1 现在逐个尝试关闭当前 run 的 child 和 root，保留首个普通异常并在清理完成后重抛，由 HookRegistry 记录脱敏 failure type。新测试覆盖第一个 child 的 end 失败后，tool 与 root 仍被调用 end；M9.6 切片状态为 `completed`。
