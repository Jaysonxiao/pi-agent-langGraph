# M5 — 流式事件与 CLI 闭环

## A. 从整体看本阶段

```text
M1-M4 completed                 M5 in_progress                     M6+ pending
用户输入 -> LangGraph 运行 -> stream chunks -> 稳定 StreamEvent -> JSONL/CLI -> 用户
                                        ^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^
                                        本阶段负责
```

M4 已经让 Agent 能安全执行文件和进程工具，但调用方目前只能等待完整 `invoke()` 结果。M5 要让运行中的模型、工具、错误和最终状态以稳定事件流呈现，并建立可交互 CLI。CLI 不应直接理解 LangGraph 的内部 chunk 形状，而应只消费本项目自己的事件 DTO。

本阶段范围包括 `astream()`/`stream()` 投影、message/token/tool/custom/state 事件、稳定 JSONL、CLI、Ctrl+C 取消和 fake-provider 端到端演示。会话持久化、断点续跑和历史分支属于 M6。

## B. 当前纵向切片：updates 投影

### B1. 一个请求如何流过当前断点

贯穿请求仍是 `hello -> fake model -> final answer`。本地 LangGraph 1.2 API 以 `stream_mode="updates"` 运行时，当前 fake 图实际产生：

```python
{
    "model": {
        "messages": [AIMessage(...)],
        "status": "completed",
        "error": None,
    }
}
```

后续 adapter 会拆出外层节点名，再调用本切片：

```text
node_name="model" + update={messages, status, error}
  -> project_stream_update(..., sequence=0)
  -> StreamEvent(kind="state_update", node="model", payload={status, error})
  -> model_dump_json()
```

`AIMessage` 不应在本切片直接复制到 payload：消息和 token 需要专门、稳定的字段投影，否则 CLI/远程客户端会依赖 LangChain 类的内部序列化形状。

### B2. Pi 设计与 Python/LangGraph 映射

- Pi 的 agent loop 发布结构化生命周期/消息/工具事件，coding-agent 再将其投影给 interactive、print 或 RPC 消费者。事件契约和 UI 表现是两个边界。
- LangGraph `stream_mode="updates"` 给出每个节点的状态增量，`messages`/`custom` 模式则负责 token/自定义事件；本项目不会把这些原始形状直接暴露为长期协议。
- `StreamEvent` 是稳定 envelope：sequence 保证调用方顺序，kind 说明语义，node 标明来源，payload 只承载 JSON 兼容数据。
- 本切片只处理 update 状态，不执行图、不输出终端、不生成 message/token 事件。

## C. 唯一学习任务

- 目标文件：`src/pi_agent/events/stream.py`
- 目标签名：`project_stream_update(node_name: str, update: Mapping[str, object], sequence: int) -> StreamEvent`
- 输入：一个已经从 LangGraph 外层 chunk 拆出的节点名、节点状态增量和调用方分配的递增序号。
- 输出：严格、JSON 可序列化的 `StreamEvent`。
- 分类优先级：

```text

```

### H3. 唯一学习任务

- 目标文件：`src/pi_agent/events/adapter.py`
